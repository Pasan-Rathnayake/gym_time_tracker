# Gym Workout Tracker

A mobile-first workout tracker PWA with two workout days: **Day 1, Chest &
Shoulders** and **Day 2, Legs & Triceps**. Pick the day at the top of the
list; each day keeps its own progress. It walks you through each
workout with a get-ready countdown, set timer, automatic rest timers, reminders
during rest and a live "time left" estimate. It works offline and can be
installed to your home screen.

## Setup

Requires Node 18+.

```bash
npm install
npm run dev        # dev server on http://localhost:5173 (also on your LAN)
npm test           # engine unit tests (Vitest)
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build locally
```

### Using it on your phone

`npm run dev` listens on your local network, so you can open the printed
`Network:` URL on your phone (same Wi-Fi). The service worker and install
prompt need HTTPS (or localhost), so to install it properly deploy `dist/` to
any static host with HTTPS (Netlify, Vercel, Cloudflare Pages, GitHub Pages…).
When the workout isn't running, an in-app card offers **Install** (Android /
desktop Chrome) or **Add to Home Screen** instructions (iPhone). You can also
use the browser menu. After the first visit it runs fully offline.

## Editing the workout

Everything lives in [`src/config/workout.ts`](src/config/workout.ts):

| Export | What it controls |
|---|---|
| `INCLUDE_TIMED_BLOCKS` | `false` (current) runs lifts only. Set it to `true` to bring back the treadmill run, warm-up and cool-down. |
| `PUSH_DAY_ITEMS`, `LEG_DAY_ITEMS` | Each day's exercises, in order. Use `lift(id, name, sets, { compound, reps, tag, note, durationSec })` for lifts (reps default to 10, set length to 40s) and `timed(id, name, type, minutes)` for treadmill / warm-up / cool-down blocks. |
| `DAYS` | The days on the day picker: name, header title, items and the storage key for that day's progress. Add an entry here to add a third day. |
| `LIFT_SET_SEC` | Default length of a lift set (40s). Leg Extension uses 80s because it's done one leg at a time. |
| `READY_SEC` | Length of the get-ready countdown (10s). |
| `REST_LOCK_SEC` | How long the start/skip buttons stay locked at the start of a rest (30s). |
| `WATER_LINE`, `TIPS` | The rest-time reminder lines. |
| `FORM_CUES` | One-line form cue per lift, keyed by item `id`. |
| `GUIDES` | Guide shown during the timed blocks, keyed by item `id`. |

Rest plans and their rules are in [`src/engine/rules.ts`](src/engine/rules.ts)
(`REST_PLANS` and `restAfter`).

Notes:

- `id` is how saved progress is matched up, and must be unique across all
  days. Keep ids stable while a workout is in progress. If you add, remove or resize items, saved progress is
  repaired automatically on the next load.
- Keep the cool-down's `type` as `'cool'`. "Bench busy" always moves items
  in front of it.
- `compound: true` gives an exercise the longer rest under plan 3. Its tag
  shows "Press" unless you set `tag` (leg day uses "Compound").
- Timed blocks are only defined for Day 1 so far.
- `src/engine/engine.test.ts` asserts the plan totals: Day 1 is 65 / 47 / 53 min
  lifts only (80 / 62 / 68 min with the timed blocks); Day 2 is 77 / 57 / 64 min.
  Update those numbers if you change the workout.

## How it works

- **Engine (`src/engine/`)**: pure TypeScript, no React. `session.ts` holds the
  state machine (`idle → ready → work → rest → idle/ready … → complete`) as a
  reducer. Every timer stores absolute timestamps (`endAt`), and a `tick`
  action catches up on any phase boundaries that passed while the phone was
  asleep. `rules.ts` holds the rest rules and plan totals, and `reminder.ts`
  picks the reminder text.
- **Hooks (`src/hooks/`)**: `useTicker` (200ms clock while active),
  `usePersistentState` (localStorage, also flushed when the page is hidden),
  `useWakeLock` (screen wake lock with a muted-video fallback, re-acquired on return),
  `useSound` (Web Audio tones, unlocked on first tap), `useInstallPrompt` (in-app install
  card) and `useLockScreenTimer` (Media Session lock-screen countdown, on by default).
- **Components (`src/components/`)**: Header, PhaseTimer, GymMode, Stopwatch,
  RestPlanPicker, ReminderCard, ExerciseCard, SetChip and Toast. `phaseView.ts`
  decides what the timer shows; PhaseTimer and GymMode both use it.
- **PWA**: `vite-plugin-pwa` generates the manifest and a Workbox service
  worker that precaches the app shell and fonts (fonts are bundled via
  `@fontsource`, so there are no network calls). Icons are generated by
  `npm run icons` (`scripts/gen-icons.mjs`). `useInstallPrompt` + `InstallCard`
  offer an in-app install path; `useLockScreenTimer` drives lock-screen
  media controls while a workout runs.

## Lock-screen timer

At the bottom of the list, **Lock-screen timer** (on by default) publishes the
current phase to the phone's media controls via the Media Session API. While a
workout is running it shows something like `Rest 1:23` / `Next: Incline DB
Press · Set 2 of 4`, with a progress bar for the phase. The phone keeps the
bar moving while locked; the title text only updates while the page is allowed
to run. The lock-screen next button runs the primary action (Done early /
Start next set / Skip rest).

**This pauses your music** (Spotify, Apple Music, etc.) — any playing audio
takes over the phone's audio session. Leave it off if you want music during
the workout.

## Gym mode

Tap **Gym mode** (next to the workout stopwatch) for a full-screen dark view
built for glancing at mid-set: a huge countdown, the phase in colour (orange
work, blue rest, green done), the next exercise, the rest reminder and big
buttons. Tap ✕ to go back. The choice is remembered on that device.

**Leave the screen on rather than locking the phone.** Mobile browsers pause
web pages when the phone is locked, so the countdown and sounds stop until you
unlock (the timers still keep the right time). While a workout is running or
gym mode is open, the app keeps the screen awake:

1. It uses the Screen Wake Lock API when the browser allows it.
2. Otherwise it plays a tiny muted looping video (from
   [NoSleep.js](https://github.com/richtr/NoSleep.js), MIT). Because it's
   muted, it doesn't interrupt your music.

The bottom line of gym mode says which one is active. If it says the browser
can't keep the screen on, set **Settings › Display & Brightness › Auto-Lock**
to **Never** for your workout.

## Behaviour notes

- After a timed block (or the last lift before the cool-down) there's no rest.
  The app returns to "Up next" with a `Next: …` toast, and you tap
  **Start set** when you're ready.
- For the first 30 seconds of a rest (`REST_LOCK_SEC`), **Start next set**,
  **Skip rest** and the set cards are locked; the skip button shows the
  seconds until it unlocks. After that you can start early or skip. **Skip
  rest** ends the rest and returns to "Up next". When the rest hits zero you
  get 3 beeps, a vibration and a toast, and the timer counts up in overtime.
- Switching rest plans during a rest re-times it under the new plan, keeping
  the time already spent.
- Pull-to-refresh is blocked, and while a workout is running the browser asks
  before reloading or closing (Chrome on Android/desktop; iPhone browsers skip
  this prompt). A reload never loses progress, but browsers silence sound until
  the next tap, so the app shows a "tap to turn sound back on" banner.
- Progress survives reloads and phone locks via localStorage. **Reset
  workout** needs a second tap within 4 seconds.
